## PR 42 — Graph Views API (behavior-neutral)

**Goal:** Passes consume **graph views** (from handles) instead of reaching into `attachments.*`. Initially alias the attachments.

**Files & steps**

1. `crates/render_wgpu/src/gfx/renderer/graph.rs`

   * In the compiled graph type, add:

     ```rust
     struct CompiledGraph {
       names: Vec<&'static str>,
       passes: Vec<PassDecl>,
       handle_ix: FxHashMap<Handle<Img>, usize>,
       views: Vec<wgpu::TextureView>, // filled per-frame
     }
     ```
   * In `compile(..)`, assign a stable `usize` index per `Handle<Img>` and fill `handle_ix`.
   * In `execute(..)`, before iterating passes, **alias** handles to attachments:

     ```rust
     self.views.resize(self.handle_ix.len(), /*dummy*/);
     for (h, ix) in &self.handle_ix {
       match image_kind_of(h) { // however you store it
         ImageKind::Color { .. } => self.views[*ix] = renderer.attachments.scene_view.clone(),
         ImageKind::Depth { .. } => self.views[*ix] = renderer.attachments.depth_view.clone(),
       }
     }
     ```
   * `ExecCtx`:

     ```rust
     impl<'a> ExecCtx<'a> {
       #[inline] pub fn view_color(&self, h: Handle<Img>) -> &wgpu::TextureView {
         &self.graph.views[*self.graph.handle_ix.get(&h).unwrap()]
       }
       #[inline] pub fn view_depth(&self, h: Handle<Img>) -> &wgpu::TextureView {
         self.view_color(h) // same storage; kind is validated by how you declared IO
       }
     }
     ```

     (Store `&CompiledGraph` inside `ExecCtx`—you already pass the graph context, or add it.)

2. `crates/render_wgpu/src/gfx/renderer/passes_graph.rs`

   * Replace **every** `&ctx.renderer.attachments.scene_view` with `ctx.view_color(color)`.
   * Replace `&ctx.renderer.attachments.depth_view` with `ctx.view_depth(depth)`.

**Tests (CPU)**

* Build/compile only (existing hazard tests stay intact).
* Optional: a tiny unit test that `handle_ix` assigns distinct indices to distinct handles.


## PR 44 — Optional Aliasing (feature `graph_aliasing`, default OFF)

**Goal:** Reuse allocations for **non-overlapping** lifetimes to reduce VRAM.

**Files & steps**

1. `renderer/graph.rs`

   * `#[cfg(feature = "graph_aliasing")]` add interval packing:

     ```rust
     struct PoolKey { format: wgpu::TextureFormat, size: glam::UVec2, msaa: u32, usage: wgpu::TextureUsages }
     struct PoolEntry { key: PoolKey, live: Live, tex: wgpu::Texture }
     ```
   * For each `ImagePlan` in order:

     * Try to find a `PoolEntry` with same `key` and `plan.live.first > entry.live.last` (disjoint).
     * If found, reuse `entry.tex` and update `entry.live = plan.live`; else create a new texture and push into pool.
   * `RA_GRAPH_TRACE=1`: log assignments for debugging.

**Tests (CPU only)**

* Interval packing logic: three intervals (A[0–2], B[3–5], C[2–4]) → A and B can share, C cannot share with A but could share with B if disjoint; assert packing behavior.

**Acceptance**

* Feature OFF: parity, `xtask ci` green.
* Feature ON (local): smoke run, no hazards.

**Docs**

* Update `risk-and-test-plan.md` with aliasing flag & guardrails; log PR 44.

## PR 45 — MSAA End-to-End (behavior-neutral toggle)

**Goal:** Main renders at `msaa_samples`, resolves to single-sample **HDR** for post.

**Files & steps**

1. **Thread sample count**

   * Ensure `attachments.msaa_samples` (u32) is available and correct.
2. `render.rs` (graph build path)

   * Build images:

     ```rust
     let samples = r.attachments.msaa_samples;
     let hdr  = gb.image(ImageKind::Color { format: HDR_FMT,   size, msaa: 1 });
     let depth= gb.image(ImageKind::Depth { format: DEPTH_FMT, size, msaa: samples });
     ```

   * Else:

     * Begin pass on `ctx.view_color(hdr)` (no resolve).
4. **Pipelines**

   * Ensure **Main** pipelines are created with `sample_count = samples` (they must match the target sample count).

**Tests**

## Pitfalls to avoid

* **Usage flags:** if you **write** then **sample** a color image later, include both `RENDER_ATTACHMENT | TEXTURE_BINDING`.
* **Depth sampling:** SSR/SSGI read depth; mark `.reads(depth)` and ensure depth image usage includes `TEXTURE_BINDING`.
* **MSAA resolve target:** post must read **single-sample** HDR; never sample MSAA textures.
* **Aliasing:** only alias **exactly** matching descriptors (format/size/msaa/usage superset) and **non-overlapping** lifetimes.
